EXERCISE 5d

Durbin test and incomplete blocks

When an assessor cannot taste every sample: the balanced incomplete block design.

Script (SK): cvicenie5d.RScript (EN): exercise5d.R🎓 Slides

What you will learn

  • to tell a complete block design from an incomplete one,
  • the conditions of a balanced incomplete block design (BIBD),
  • to use the Durbin test and its post-hoc comparisons.

Why incomplete blocks?

The Friedman test assumes complete blocks: every assessor tastes every sample. With 6 – 7 strongly flavoured samples (cheeses, smoked meats, spirits, hot sauces) this is not realistic – fatigue and receptor adaptation set in and the last samples are rated worse. The solution is for each assessor to receive only part of the samples, but according to a plan that guarantees a fair comparison.

Balanced incomplete block design (BIBD)

For all samples to be comparable, the plan must meet three conditions:

ParameterMeaningExample from the script
tnumber of samples7 (A – G)
bnumber of blocks (assessors)7
ksamples per block3
rhow many times each sample is rated3
λhow many times each pair of samples meets at the same assessor1
b · k = t · r    and    λ = r (k − 1) / (t − 1) 7 · 3 = 7 · 3 = 21 ratings; λ = 3 · 2 / 6 = 1 – every two samples are compared directly exactly once.

BIBD plans are tabulated (e.g. Cochran & Cox) and can also be generated in R (package crossdes, function find.BIB()). The plan is then repeated with further groups of assessors to increase the number of ratings.

Durbin test

The Durbin test generalises the Friedman test to incomplete blocks. Samples are ranked within each block (1 … k), the ranks of each sample are summed and compared with the expected sum r(k + 1)/2. For complete blocks it gives the same result as the Friedman test – which is what the first part of the script demonstrates.

library(PMCMRplus)
durbinTest(y)                                   # global test; NA = sample not rated
durbinAllPairsTest(y, p.adjust.method = "none") # pairwise comparisons
Data formatA matrix: rows = blocks (assessors), columns = samples, NA where the assessor did not receive the sample. For post-hoc comparisons it is sensible to use a correction ("holm", "bonferroni") – "none" in the script is only for demonstration.
The PMCMR packageThe original PMCMR package (functions durbin.test, posthoc.durbin.test) is no longer on CRAN. Its successor PMCMRplus uses the names durbinTest and durbinAllPairsTest.
